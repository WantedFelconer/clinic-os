// ============================================================================
// KEY ARCHITECTURAL NOTES
// ============================================================================

  1. All server "models" are Plain Old JavaScript Objects (POJOs),
     not ES6 classes or ORM entities. They are singleton DAO objects.

  2. No TypeScript interfaces or classes on the server - all plain JS
     with CommonJS module system (require/module.exports).

  3. Client is a single-file React SPA (App.tsx, ~3167 lines) that renders
     all views conditionally with inline mock data during development.

  4. No client-side router - views are conditionally rendered via state
     (currentView string).

  5. Multi-tenant architecture: all resources are scoped under the URL
     pattern /api/clinics/:clinicId/*

  6. UUID v4 for all primary keys across all 19 database tables.

  7. Soft deletes via is_active boolean on User, Clinic, Patient,
     Prescription, PrescriptionItem, ClinicService, ConsultationPackage,
     and ClinicStaff.

  8. JWT authentication + role-based authorization (patient, doctor,
     assistant, admin) + clinic staff membership validation.

  9. JWT payload contains { id, email, role }.

 10. MySQL2 connection pool (Promise-based) exposed as { query, execute,
     getConnection, pool }.

 11. Request flow: HTTP -> Security Middleware -> AuthMiddleware.authenticate()
     -> RBACMiddleware.authorize(roles) -> clinicAccess() -> Route ->
     Controller.method() -> Model.method() -> ErrorHandler -> JSON Response.

 12. MySQL error codes mapped in errorHandler: 1062 (duplicate), 1048
     (NOT NULL), 1452 (FK violation), 1265/1406 (truncation).

 13. 48+ shadcn-style UI components on the client under components/ui/.

 14. Server ENV config via .env: DB_HOST, DB_PORT, DB_USER, DB_PASSWORD,
     DB_NAME, JWT_SECRET, JWT_EXPIRES_IN, PORT.

(End of file)
